Turning a reference book into something you can explore

Reference books are full of connections a reader can’t follow: who played on what, which label, which critic praised it. We are turning a published jazz guide and two open music databases into a graph, so that every name leads somewhere and, once search is built, every answer can be traced to its source.

Why not just a chatbot?

Point a chatbot at a PDF and you get fluent answers you can’t check, and a dead end after each one. People don’t use a reference book that way. They look something up, notice a name, and follow it.

So the graph comes first, and it exists today. Search and chat come next, and are not built yet. The plan: search that resolves vague input (“newks time”, “blue note 4001”) to a real album, then lets you move along the connections to the personnel, the label and the other records each musician played on. Chat will be a supporting feature that shows where each answer came from.

Built by agents, supervised by people

Jazz Atlas is also our test bed for autonomous AI workers. Some stages of the build were bounded tasks on a task board, each with a written definition of done: an AI worker did the work and proved it to an automated check, and a person signed off before the next stage began. People planned the stages and made several of the key fixes.

  • Prove the smallest unit first

    The first autonomous run did one thing: start the database and prove it answered. 22 tool calls, two and a half minutes, no help. Everything later was built on that.

  • Read the log before theorising

    Building connections was 180× slower than it should have been. The cause was a missing index, found in the logs, not by guessing, and a person added it. Indexes now come first.
