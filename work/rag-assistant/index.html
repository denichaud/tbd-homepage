Live · Client website & AI assistant

An AI assistant that answers from the consultant’s own work

A consulting practice had years of writing, talks and course material that visitors never found. We designed and built a custom website around that library, an assistant that answers only from it and says so when the library has no answer, and a private drafting desk that turns the same material into first drafts.

3,210searchable passages

Self-hostedretrieval, running on our own infrastructure

The problem

The material was the practice’s real asset: workshop notes, exercises, talks and articles built up over years. On the old site it sat in a list of downloads. A visitor with a specific question had no way to find the one page that answered it.

A generic chatbot would have made things worse. It would answer confidently from general knowledge, in a voice that wasn’t the consultant’s, with nothing to check it against.

What we built

The website itself is a hand-built WordPress theme with no page builder. The assistant is a plugin that calls a retrieval service we run on our own servers, so the client’s library is never handed to a third-party search product. The answer itself is written by a hosted language model, using only the passages we retrieve.

The same library powers a private drafting desk inside the consultant’s WordPress dashboard. They choose a topic and a length, and within about half a minute a first draft built only from their own material is saved for them to edit. It never publishes on its own, and when the material on a topic is too thin, it says so rather than padding.

  • WordPress (custom theme + plugin)
  • FastAPI
  • PostgreSQL + pgvector
  • gte-small embeddings
  • Cross-encoder re-ranking
  • Hosted LLM for answers
  • Kubernetes (k3s) + GitOps
  • Cloudflare Zero Trust

Seeing what the library covers

Retrieval systems are usually a black box: a question goes in, an answer comes out, and nobody can say what the system knows. So we built a map. Every passage in the library is a dot, placed so that passages on similar topics sit together. The questions real visitors asked are laid on top, coloured by how well the library could answer them.

What measuring it taught us

  • A bug that no demo would have caught

    Our first measurement blamed missing content. Chasing one upload that never showed up in answers, we found the real cause: a database index quietly returning the wrong passages. Re-running the check confirmed the fix: the same test question scored −3.7 before and +4.7 after. The assistant had looked fine in casual use the whole time.

  • The obvious metric was useless

    Similarity scores looked like a natural quality signal. They weren’t: questions the library could not answer scored almost exactly as high as two random passages compared with each other. We judge answers with the re-ranking model instead.

  • Gaps become a writing plan

    Questions that land in empty space on the map show the client exactly which topics visitors ask about and the library doesn’t cover. That turns “improve the AI” into a list of articles to write.

  • Saying “I don’t know” is a feature

    When the library has no good answer, the assistant says so and offers a conversation. For a consulting practice, a visitor who reaches out is a better outcome than a plausible-sounding guess.
